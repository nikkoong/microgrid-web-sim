# AGENTS.md

Browser-based solar microgrid management game. Vanilla HTML5 Canvas + JS, no frameworks, no build tools, no npm. [Play live](https://solarmicrogrid.vercel.app/).

## Run

```bash
python -m http.server 8000
# or
npx http-server -p 8000
# then open http://localhost:8000
```

No build step. No test suite. No linter. Verify by opening browser DevTools and checking the console.

## Quick test commands (browser console)

```javascript
Game.gameState                          // inspect state
Game.gameState.triggerWeatherChange()   // force weather event
Game.gameState.eventSystem.triggerRandomEvent()  // force crisis event
Game.activateCheat()                    // +$50k, full batteries (cheat: type "mmm")
```

## Architecture

### Script load order (index.html) — matters

`gameState.js` → `eventSystem.js` → `uiFramework.js` → `camera.js` → `visualRenderer.js` → `economicSystem.js` → `main.js`

Each file exports classes via `window.ClassName`. `main.js` is last because it references everything.

### Key globals

| Global | Role |
|--------|------|
| `Game` | Singleton in `main.js`. Game loop, rendering, input handling. |
| `Game.gameState` | Central `GameState` instance. All game data lives here. |
| `Game.camera` | `Camera` instance. Screen↔world coordinate transforms. |
| `Game.worldRenderer` | `WorldRenderer`. Draws grid, entities, connections, weather. |
| `Game.notificationSystem` | `NotificationSystem`. Toast-style messages. |
| `Game.purchaseManager` | `PurchaseManager`. Equipment catalog + buy logic. |
| `window.StorageManager` | Static class for localStorage save/load. |

### File map

| File | What it contains |
|------|-----------------|
| `js/gameState.js` | `GameState` (energy calc, weather, goals, satisfaction) + `StorageManager` |
| `js/eventSystem.js` | `EventSystem` — crisis events with execute/updateEffect/onComplete lifecycle |
| `js/uiFramework.js` | `Button`, `Panel`, `Dialog`, `EnergyBar`, `NotificationSystem`, `MobileDrawer`, `MobileBottomSheet`, `MobileShopContent`, `MobileSelectionContent` |
| `js/camera.js` | `Camera` (pan/zoom/coordinate transform) + `TouchHandler` (pinch-to-zoom, tap, long-press) |
| `js/visualRenderer.js` | `SpriteManager` (procedural sprites), `ParticleSystem`, `WorldRenderer` |
| `js/economicSystem.js` | `EquipmentCatalog`, `PurchaseManager`, `ShopMenu` |
| `js/main.js` | `Game` singleton — init, game loop, input, placement system, HUD, mobile UI, rendering |

## Critical quirks

### Time system
1 real second = 1 game hour. `deltaTime` in `update()` is in seconds but functions as game hours. See `gameState.js:161`.

### Canvas is 1200×800 logical
High-DPI aware: physical pixels = logical × `devicePixelRatio`. Context is pre-scaled. Mouse/touch coordinates must be converted from CSS→logical using `scaleX = 1200 / rect.width`.

### Coordinate spaces
- **Screen space**: UI elements (buttons, panels) live here. `handleUIClick()` uses these.
- **World space**: Game entities live here. `handleWorldClick()` uses `camera.screenToWorld()`.
- Entities store game-relative coords. Rendered at `(offsetX + entity.x, offsetY + entity.y)` where `offsetX=50, offsetY=100`.

### Entity IDs are sequential
Generated by `PurchaseManager.generateSequentialId()`: `panel_01`, `panel_02`, `battery_01`, `home_01`, etc. All household types share the `home_` prefix.

### Tier system
Solar/Battery: `tier1` → `tier2` → `tier3` → `tier4`. Tier4 has special abilities:
- **Solar tier4**: WEATHERPROOF — immune to weather events, still affected by nighttime
- **Battery tier4**: SELF-HEALING — immune to battery events, passive 0.5% charge regen/hour

Household tiers: `cabin`, `family`, `business`, `corporate`. Corporate has GROWTH mechanic (income increases $1/day up to $75/hr).

### Money flow
- Earn: hourly income from households (scaled by type + satisfaction bonus)
- Spend: equipment purchase, upgrades (cost = next tier price − current tier price)
- Sell: 50% refund on deletion
- Goals: $500 bonus per completed goal

### Placement system
Money is deducted on `startPlacement()`, refunded on `cancelPlacement()`. `addEquipment()` places the entity at the final position. Camera panning is disabled during placement on mobile.

### Mobile vs Desktop
Detected via `Game.isMobile` / `Game.isTouch`. Mobile uses `MobileDrawer` (shop), `MobileBottomSheet` (entity selection), `TouchHandler` (gestures). Desktop uses `ShopMenu` panel + inline selection UI.

### Event system
Events use `function()` (not arrow functions) in `execute`/`onComplete` so `this` refers to the event object. Events track `executed` flag to prevent double-application. Entity-debuff events (malfunction, demand spike) store original values in closure and restore on complete.

### localStorage
Key: `microgrid_game_save`. Save/load via `StorageManager.saveGame()` / `StorageManager.loadGame()`.

## Style conventions

- Classes: PascalCase. Variables/functions: camelCase. Entity IDs: snake_case.
- `const` by default, `let` when needed, never `var`.
- Arrow functions for callbacks. Regular methods for class methods.
- All cross-file access via `window.ClassName` exports.
- Entity data stored as plain object literals in arrays (`gameState.solarPanels`, etc.).
- Pokemon-inspired UI: tan/beige panels, bold monospace text, colored status indicators.

## Adding features

1. New class → separate file in `js/`, export via `window.ClassName`
2. Add `<script>` tag in `index.html` (order matters — after dependencies)
3. Test in browser console before wiring into Game loop
4. No external dependencies — everything is hand-rolled
